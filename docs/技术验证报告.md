## 二、七项关键发现

这些是实现阶段会直接踩坑的地方，验证阶段提前挖出来了。

### 1. `get_texttrace()` 的字符包围盒宽度恒为 0

`get_texttrace()` 是 PyMuPDF 最低层的文本接口，给出字形 ID、字体、方向、z 序——
但它的字符 bbox 是 `(x, y0, x, y1)` 这样的退化竖线，**宽度永远是 0**。
而 `rawdict` 的 bbox 准确，却又不提供字形 ID。

**对策**：两个来源按字符原点配对。`rawdict` 建 `原点 → bbox` 索引，
遍历 `get_texttrace()` 时查表取回准确坐标。
若直接采信 `get_texttrace()` 的坐标，后续所有擦除和重画都会错位。

实测影响：标题「设备采购合同」的框会短一个字宽（333.5 而非 351.5）。

### 2. `get_texttrace()` 的 span ≠ 视觉行

`get_texttrace()` 按**内容流里的文本对象**分组 span，而 `insert_textbox` 之类
会把整个段落写成一个文本对象。于是一个 span 里混着好几行、基线各不相同的字符。

实测影响：三行折行的段落被当成一行处理，段落分析、字体度量、重排全部失准。

**对策**：按基线把 span 拆成多个，容差 `0.25 × 字号`
（远低于行距 `1.5 × 字号`，又高于噪声）。

### 3. PyMuPDF 无法使用 PDF 内嵌的子集字体（静默陷阱）

把 `doc.extract_font()` 拿到的字体 buffer 传给 `pymupdf.Font()`，
再交给 `TextWriter` 绘制——**不会报错，文字也能正确提取，但渲染出来是另一个字体**。

实测：写入的 PDF 里字体名变成了 `Droid Sans Fallback Regular`（MuPDF 内置 CJK 兜底字体）。
原文档是宋体，重绘后变黑体，视觉差异明显。

另外 `Font.has_glyph()` 对这类嵌入字体**恒返回 0** —— 因为子集字体没有 cmap 表，
字形名是 `glyph00001` 这种，压根没有 Unicode 映射。这条路是死的。

**对策**：走**系统字体匹配**。原字体是 SimSun、系统也有 SimSun，匹配后渲染外观完全一致。
匹配是否成功必须量化验证：用原文档中该行的**实测渲染宽度**与候选字体的计算宽度比对，
比值 ≈ 1.0 才算同字体。实测 31/31 块精确等于 1.0000。

### 4. `apply_redactions` 的 `graphics` 默认值会删光矢量图形

默认值 `PDF_REDACT_LINE_ART_REMOVE_IF_COVERED` 会把被擦除框覆盖的矢量图形一并删除。

实测（擦除表格区域）：

| 参数 | 矢量图形对象 | 结果 |
|---|---|---|
| 默认 `REMOVE_IF_COVERED` | 27 → **2** | 表格框线全毁，多损失 15000 像素 |
| 显式 `LINE_ART_NONE` | 27 → **27** | 框线完整保留 |

**对策**：必须显式传 `graphics=PDF_REDACT_LINE_ART_NONE`，同时 `images=PDF_REDACT_IMAGE_NONE`
避免背景图被打洞。

### 5. `apply_redactions` 会连带删除水印 —— 固定层必须主动重绘

`apply_redactions` 删除的是「**任何包围盒与擦除矩形相交的字符**」，不管它属于哪一层。

水印是斜跨整页的旋转文本，包围盒巨大（146.6,311.4)–(447.8,529.6)），
与正文区必然重叠。实测擦除一条正文行就削掉水印的一两个字，擦满一页水印整个消失。

**对策**：固定层保护不能只是「不去碰它」，必须在 `apply_redactions` **之前**
记录会被波及的固定层元素，擦除后**原样重绘回来**（且画在内容下层，z 序才正确）。

> 这一条是像素比对发现不了的：水印与正文空间重叠，重排后正文下移，
> 那块区域的像素本来就该变，水印丢了会被「正文变化」掩盖。
> 第一次跑 Day 3 时像素比对报「区域外零差异」，是**视觉复核**才发现水印没了。
> 因此固定层必须单独做结构比对（文字/原点/方向/字号/颜色）。

### 6. `Matrix(θ)` 与方向向量符号相反

重绘旋转文本时，`pymupdf.Matrix(θ)` 产生的旋转与方向向量 `(cosθ, sinθ)` 符号相反。
直接传 `atan2(dir.y, dir.x)` 得到的角度，结果是**字符原点精确、但字形转反了**（镜像）。

实测：传 `-angle` → **0 像素差异**（逐像素复现）；传 `angle` → 21667 像素差异（215%）。

### 7. 文字未变时不应重新断行

重新断行会因为禁则规则、宽度取整等细节产生细微差异，**哪怕一个字都没改**。

实测：同一段文字重新断行后，原文「、合格证及保修凭证。」的 `、` 被禁则规则
移到上一行末尾，该行从 42 字变 43 字、宽度 441→451.5pt，**溢出栏宽**，
标点压到页边距上（12 个像素跑到块外）。

**对策**（最小位移原则的第一个应用点）：
- 文字未变 → 直接沿用原始断行，结果是真正的零漂移
- 文字变了 → 从原文档反推它的断行风格（行首出现禁则标点即证明原文用朴素断行），照搬同样风格，而不是强加更规范的排版
- 禁则悬挂必须受页面边距约束，不能无条件探出

## 三、验证过的能力

### 结构解析（`spike/extract.py`）
- L0 字符层：unicode、字形 ID、基线原点、包围盒（融合 `get_texttrace` + `rawdict`）
- L1 行层：旋转不变的投影分组，水平与任意角度旋转文本同一套逻辑
- L2 块层：段落聚合（字号/字体/颜色/重叠/行距稳定性 + 短行紧跟整行的标题特征）

### 规则引擎（`spike/classify.py`）
每条规则输出**置信度**而非硬判定，低于 0.75 标记为待确认交用户修正。

实测分类结果：页眉 0.95、页脚 0.95、水印 0.98、主标题 0.92、条款小标题 0.88、段落 0.90。

### 字体引擎（`spike/fonts.py`）
- 从 PDF 字体名识别字体族（`SimSun Regular` → simsun → `simsun.ttc`）
- 度量一致性量化验证（挑最短行做样本，避开两端对齐的拉伸干扰）
- fallback 链：同族系统字体 → 通用兜底 → 报告警告

### 编辑内核（`spike/edit.py`）
- 按行紧贴的精确擦除
- 段落级重排（折行 + 禁则 + 两端对齐 + 首行缩进）
- 旋转文本重绘
- 擦除与绘制**分阶段**（多块重排必须先擦完再画，否则后一块的擦除会毁掉前一块刚画好的内容）

### 重排引擎（`spike/reflow.py`）
- 阅读顺序排序
- 累计位移传播
- **最小位移原则**：位移 < 0.5pt 的块跳过重画，保留原文件字节
- 固定层保护：检测被波及的固定层元素并原样重绘

## 五、保真度结论（实测支撑）

| 元素 | 保真级别 | 实测证据 |
|---|---|---|
| 固定层（页眉/页脚/水印） | 位置方向字号颜色完全一致 | 4/4 元素结构一致；页眉页脚区域像素零差异 |
| 位置未变的流式元素 | **字节级 100%** | 12/14 块保持原样，整页 0 像素差异 |
| 被重排顶下去的元素 | 按原始几何重建，字体度量精确一致 | 下游 10 块重画，字体度量比 1.0000 |
| 被编辑的块 | 只有改动字符处像素变化 | 等长改字：492 px 全部落在改动字符上 |

**核心论断成立**：未受影响的部分不是「高保真重建」，而是压根没碰。

## 六、尚未验证 / 已知边界

验证只用了单栏中文合同样本，以下未覆盖，实现阶段需补测：

- **多栏排版**：xy-cut 分栏检测尚未实现（当前只按 y 排序）
- **文字环绕图片**：图片区域的文字避让未处理

- **表格内部重排**：当前表格作为刚性整体移动，单元格内文字不重排
- **公式/矢量图内文字**：未处理
- **加密 PDF**：未处理
- **扫描件 OCR**：未处理
- **字体缺失场景**：若系统没有同族字体，会退到通用兜底并告警，但外观差异未量化
- **西文断行**：当前按空格切词，未处理连字符断词

## 七、水印重绘的代价（需明确告知用户）

水印无法「字节保留」——擦除正文必然波及它，只能擦后重绘。
重绘是**逐像素精确的**（实测 0 差异），但严格来说它已经不是原始字节了。
页眉页脚若无波及则保持原字节。

这个代价应在产品中透明化：编辑报告里可以列出「本次编辑重绘了 1 个固定层元素」。
